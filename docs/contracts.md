# Контракты между приложениями

`mc-build-updater` зависит от HTTP-контракта `file-hosting`. Любое изменение этой страницы требует явного согласования: старые клиентские `.exe` могут работать в поле.

## Базовый URL

| Режим client | URL по умолчанию |
| --- | --- |
| Dev (`--dev`, в том числе `make dev-client`) | `http://localhost:1447/` |
| Production | `http://mc.sinezix.ru:1447/` |
| Явное переопределение | `MC_BU_FILE_HOSTING_URL` или `--file-hosting-url` |

Для production URL должен оканчиваться `/`; клиент нормализует отсутствие завершающего слеша.

## HTTP API file-hosting

Все маршруты поддерживают только `GET`. Другие методы получают `404`.

| Маршрут | Ответ | Назначение |
| --- | --- | --- |
| `/map/update` | `200 OK`, пустое тело | Пересканировать каталог файлов, пересчитать SHA-1 и версию карты. |
| `/map/version` | JSON-строка | Получить версию карты. |
| `/map` | JSON-массив `FileMap` | Получить метаданные всех доступных файлов. |
| `/<dir>/<sha1>` | файл | Скачать файл по SHA-1. |
| `/<dir>/<name>` | файл | Скачать файл по имени. |

Несуществующий файл отдаёт `404`.

### `FileMap`

```json
{
  "hash": "50c64ec7245c3f76a563d64c85e6ca3d549b1828",
  "path": "X:\\...\\files\\mods\\example.jar",
  "name": "example.jar",
  "dir": "mods"
}
```

| Поле | Тип | Семантика |
| --- | --- | --- |
| `hash` | string | SHA-1 содержимого файла, lowercase hex. |
| `path` | string | Абсолютный путь на host/container. Потребитель не должен использовать его для скачивания. |
| `name` | string | Базовое имя файла. |
| `dir` | string | Относительный каталог от root, с `/`; root-файлы имеют пустую строку. |

Порядок карты детерминированно сортируется по абсолютному пути. Это стабилизирует расчёт версии карты.

### Версия карты

Формат:

```text
<6 lower-case hex MD5>:<Unix timestamp в миллисекундах>
```

MD5 используется только ради совместимости версии map и не является защитным механизмом.

### Выдача файла

Успешный ответ содержит:

```http
Content-Disposition: attachment; filename="<name>"
Content-Length: <size>
```

Server строит карту из `files/` только при старте или `GET /map/update`. Изменение файла после построения карты не меняет его SHA-1 до обновления карты.

## Данные client

### Remote configuration

URL: `GET /config/remote.json`

```json
{
  "LastVersion": "alpha.4"
}
```

`LastVersion` сравнивается со строковой константой client. При несовпадении production-клиент пытается self-update.

### Карта модов ветки

URL: `GET /MM/<branch>.json`

```json
[
  {
    "hash": "50c64ec7245c3f76a563d64c85e6ca3d549b1828",
    "path": "X:\\source\\mods\\example.jar"
  }
]
```

Client использует:

- `hash` — чтобы определить актуальность и найти запись в `/map`;
- базовое имя `path` — только fallback, если запись `/map` не содержит `name`.

Для каждого `hash` из карты ветки должна существовать запись `/map`, обычно в `dir = "mods"`. Client скачивает её по `GET /mods/<hash>` и сохраняет как `mods/<name>`.

## Алгоритм синхронизации модов

1. Client вычисляет SHA-1 всех **обычных файлов первого уровня** локального `mods/`.
2. Загружает `MM/<branch>.json` и `/map`.
3. Удаляет локальный файл, если его SHA-1 нет в карте ветки.
4. Для каждого SHA-1, которого нет локально, скачивает файл из `/mods/<hash>`.
5. Загрузки выполняются максимум в 10 параллельных потоков.

Имя локального файла не определяет актуальность: решающим является SHA-1.

## Self-update contract

Production-клиент ожидает:

| URL | Назначение |
| --- | --- |
| `/static/7z_x32.exe` | 7-Zip executable, сохраняется как `7z.exe`. |
| `/static/mc-build-updater.7z` | обновление client, архив 7z с паролем `123`. |

При новой версии клиент копирует текущий executable в `update.exe`, завершает основной процесс, а копия запускается с `--apply-update`, распаковывает архив и стартует новый `mc-build-updater.exe --updated`.

Self-update доступен только на Windows и отключён в dev-режиме.
